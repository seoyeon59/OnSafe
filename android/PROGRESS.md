# OnSafe 프론트엔드 진행 현황

**기준일** 2026-08-24 · **작성** 프론트엔드

핵심 파이프라인(로그인 → 촬영 → 낙상 감지 → 이력 확인)은 실기기에서 동작을 확인했습니다.
남은 것은 실시간 영상 보기·푸시 알림과 UI 보강입니다.

> ⚠️ **UI는 추가 보강 예정입니다.** 전면 개편은 아니고, 피드백 문구·상태 표시·애니메이션 등 부분 조정 수준입니다.

---

## 1. 앱 구조

### 화면 흐름

```
로그인 ─┬─ 회원가입 (2단계 · 이메일 인증)
        └─ 로그인 성공
              ↓
         튜토리얼 → 권한 요청 → 모드 선택
                                   ├─ 보호자 모드 → 홈 · 사고이력 · 알림 · 설정
                                   └─ 카메라 모드 → 촬영 · 낙상 감지
```

### 모드 간 페어링

같은 계정으로 두 기기에 로그인하면 자동으로 연결됩니다. 별도 페어링 절차는 없습니다.
낡은 폰은 카메라 모드로 촬영하고, 보호자 폰은 그 결과를 조회합니다.

## 4. 실기기 검증 결과 (8/24)

### 4-1. 검증 환경

- 백엔드: Docker Compose 로컬 구동 (Kotlin API · Python AI · Redis)
- 앱: 실기기 USB 연결 (`adb reverse`로 로컬 서버 접속)
- 실기기로 카메라, 에뮬레이터로 보호자 모드를 접속하여 상태 변화 확인

### 4-2. 통과 항목

- 회원가입 · 로그인 · 토큰 발급
- 카메라 WebSocket 연결 및 관절 데이터 전송
- **낙상 감지** — 위험 점수 91.6 / 96.7로 명확히 감지
- 중복 알림 방지 (6시간 쿨다운) 정상 작동
- 낙상 전후 4분 영상 자동 생성
- 영상 업로드 주소 발급
- 개인정보 주소 저장 · 조회
- 화면보호기 동작

### 4-3. 미검증 항목

| 항목 | 사유 |
|---|---|

| 주제 | 쟁점 |
|---|---|
| 실시간 영상 보기 | 서버에 주소 저장 API(`GET /api/camera/url`)는 있으나 채울 주소가 없는 상태. 안드로이드 폰은 스트리밍 주소를 스스로 만들 수 없어, 어떤 카메라를 쓸지부터 결정 필요 |

| 알림 보관 기간 | 화면 문구(7일)와 서버 정책(30일) 불일치 |

### 6-3. 백엔드 공유 사항

| 이슈 | 내용 |
|---|---|
| **JWT 서명 방식 불일치** | Kotlin 서버가 키 길이에 따라 서명 방식을 자동으로 고르는데(48자 이상이면 HS384), Python 서버는 HS256만 받는 상태. **로그인은 되는데 카메라 연결만 조용히 실패**함. Python 쪽에서 algorithms를 여러 개 허용하거나 운영 키를 32~47자로 맞추면 해결됨 |
| 촬영 종료 신호 없음 | `realtime_data`가 촬영이 끝나도 남아 있어 `GET /api/camera/score`만으로는 촬영 중인지 알 수 없음. 앱은 `updated_at`이 15초간 그대로면 종료로 간주하는 방식으로 우회. 다만 정상 종료와 기기 이상을 구분할 수 없어, 구분이 필요하면 서버에 촬영 세션 개념이 필요함 |
| 시각 타임존 | `updated_at`이 타임존 없는 문자열이라 앱 시계와 직접 비교할 수 없음 (컨테이너 UTC ↔ 단말 KST) |
| 전화번호 검증 | 백엔드 정규식도 010으로 시작하는 번호의 10자리를 허용 중 |
| 함수명 불일치 | Python `get_current_user_id()`가 실제로는 이메일을 반환. 현재는 사용처가 없어 무해 |

## 7. 배포 전 필수 조치

| 항목 | 현황 |
|---|---|
| **릴리즈 서명 키** | 없음. 배포용 빌드 자체가 나오지 않음 |
| **ProGuard 규칙** | MediaPipe 관련 규칙 누락. **배포 빌드에서만 낙상 감지가 동작하지 않을 수 있음** |
| 운영 서버 주소 | 임시값 상태 |
| 약관 · 개인정보처리방침 URL | 비어 있음 (스토어 등록 필수 항목) |
| Firebase Storage | 미개설 |

> ProGuard 항목은 개발 빌드에서는 드러나지 않습니다. 배포 전환 후 실기기로 낙상 감지를 반드시 재확인해야 합니다.
