# OnSafe 프론트엔드 진행 현황

**기준일** 2026-09-03 · **작성** 프론트엔드

핵심 파이프라인(로그인 → 촬영 → 낙상 감지 → 이력 확인)은 실기기에서 동작 확인 완료.
남은 것은 실시간 영상 보기·푸시 알림·UI 보강.

UI는 부분 조정(피드백 문구·상태 표시·애니메이션) 수준의 보강이 예정돼 있음. 전면 개편 아님.

---

## 1. 앱 구조

```
로그인 ─┬─ 회원가입 (2단계 · 이메일 인증)
        └─ 로그인 성공
              ↓
         튜토리얼 → 권한 요청 → 모드 선택
                                   ├─ 보호자 모드 → 홈 · 사고이력 · 알림 · 설정
                                   └─ 카메라 모드 → 촬영 · 낙상 감지
```

**모드 간 페어링** — 같은 계정으로 두 기기에 로그인하면 자동 연결. 별도 절차 없음.
낡은 폰이 카메라 모드로 촬영하고, 보호자 폰이 결과를 조회.

## 3. 실기기 검증 (8/24)

**환경** — 백엔드 Docker Compose 로컬 구동(Kotlin API · Python AI · Redis), 앱은 실기기 USB(`adb reverse`).
실기기를 카메라 모드로, 에뮬레이터를 보호자 모드로 두고 상태 변화 확인.

**통과** — 회원가입·로그인·토큰 발급 / WebSocket 연결 및 관절 전송 / **낙상 감지(위험 점수 91.6 · 96.7)** /
중복 알림 6시간 쿨다운 / 낙상 전후 4분 영상 생성 / 업로드 주소 발급 / 주소 저장·조회 / 화면보호기

**미검증**

| 항목 | 사유 |
|---|---|
| 영상 저장 · 재생 · 다운로드 | Firebase Storage 미개설 |
| 푸시 알림 수신 | FCM 미구현 |
| 이메일 발송 (인증 · 비밀번호 재설정) | 로컬 환경에 메일 설정 없음 |

## 4. 미해결 — 팀 결정 필요

| 주제 | 쟁점 |
|---|---|
| **실시간 영상 보기** | 메인 기능이나 방식 미정. 서버에 주소 저장 API(`GET /api/camera/url`)는 있으나 채울 주소가 없음. 안드로이드 폰은 스트리밍 주소를 스스로 만들 수 없어 어떤 카메라를 쓸지부터 결정 필요. 결정 전까지 앱 착수 불가 |
| 홈 화면 상단 표시 | 이름·기기 ID가 고정 문구. 기기 등록 API(Python `/api/devices`)는 있으나 미사용 결정. 기기 ID 칸을 연결 상태 표시로 대체하는 방향. 보호자 이름 노출 여부도 함께 결정 필요 |
| 낙상 오탐 쿨다운 | 설치 중 오탐이 나면 6시간 감지 차단. 해제 수단 필요 |
| 백그라운드 촬영 | 홈으로 나가도 촬영 지속. 사용자가 종료로 오해할 소지 |
| 알림 보관 기간 | 화면 문구(7일)와 서버 정책(30일) 불일치. 문구 수정 / 클라이언트 필터 / 서버 파라미터 중 택일 |
| 비밀번호 허용 문자 | 앱 정규식이 특수문자를 `@$!%*#?&`로 한정. 서버 검증 규칙과 일치 여부 확인 필요 |

## 7. 배포 전 필수 조치

| 항목 | 현황 |
|---|---|
| **릴리즈 서명 키** | 없음. 배포용 빌드 자체가 나오지 않음 |
| **ProGuard 규칙** | MediaPipe 관련 규칙 누락. 배포 빌드에서만 낙상 감지가 동작하지 않을 수 있음 |
| **주소 검색 API 키** | `AddressSearchViewModel.CONFM_KEY` 평문 커밋 상태. `local.properties` + `BuildConfig` 분리 및 키 재발급 필요 |
| 운영 서버 주소 | 임시값 |
| 약관 · 개인정보처리방침 URL | 비어 있음 (스토어 등록 필수 항목) |
| Firebase Storage | 미개설 |

ProGuard 항목은 개발 빌드에서 드러나지 않음. 배포 전환 후 실기기로 낙상 감지 재확인 필수.

## 8. 백엔드 공유 사항

### 8-1. 조치 요청

| # | 항목 | 우선순위 |
|---|---|---|
| 1 | **JWT 서명 방식 불일치** — Kotlin 서버가 키 길이에 따라 서명 방식을 자동 선택(48자 이상이면 HS384)하는데 Python 서버는 HS256만 수용. 로그인은 되지만 카메라 연결만 조용히 실패. Python에서 algorithms를 여러 개 허용하거나 운영 키를 32~47자로 통일하면 해결 | 높음 |
| 2 | **`POST /api/devices/{user_id}` 재등록 409** — 같은 소유자가 같은 기기를 다시 등록하면 409 반환. 명세 v4.2의 "upsert"와 구현 불일치(`devices/service.py register_device()`). 앱이 카메라 모드 진입마다 호출하므로 최초 1회 외에는 `last_seen` 미갱신 + 409 누적. 현재 앱은 실패를 무시해 사용자 영향은 없음. 같은 소유자면 `device_name`/`last_seen` 갱신 후 200 반환 요청 | 높음 |
| 3 | **`devices.status` / `last_seen` 미갱신** — `register_device()`가 `inactive`로 기록한 뒤 갱신하는 코드가 없고 `/ws/stream`도 `devices` 컬렉션에 쓰지 않음. 결과적으로 카메라가 정상 동작 중에도 항상 `inactive`. `/ws/stream`의 `init` 수신 시 `status: active` · `last_seen: now` 갱신 + 조회 시 임계 시간(예: 30초) 초과분을 `offline` 판정하는 처리 요청. 반영되면 앱의 연결 상태 판정을 폴링에서 서버 값 기반으로 전환 가능 | 높음 |
| 4 | **`/ws/stream` 토큰이 쿼리스트링** — `ws://.../ws/stream?token=...` 형태라 프록시·LB·서버 접근 로그에 토큰이 평문 축적. `Authorization: Bearer` 또는 `Sec-WebSocket-Protocol` 인증 지원 요청. 앱은 OkHttp라 WS 핸드셰이크에 헤더 부착 가능하며, 서버 지원 시 `LandmarkStreamClient.connect()` 한 곳만 수정 | 중 |
| 5 | **`/api/devices/*` 운영 라우팅 확인** — Kotlin 서버에 해당 경로가 없어 앱이 Python 서버를 직접 호출 중. 운영에서 `https://api.neulbom.com/api/devices/*`가 Python으로 프록시되는지 확인 요청. 별도 호스트/포트를 쓴다면 주소를 알려주시면 `AI_BASE_URL`을 맞춤 | 중 |

### 8-2. 공유 (조치 불필요)

| 항목 | 내용 |
|---|---|
| 촬영 종료 신호 없음 | `realtime_data`가 촬영 종료 후에도 남아 `GET /api/camera/score`만으로는 촬영 여부 판별 불가. 앱은 `updated_at`이 15초간 고정이면 종료로 간주하는 방식으로 우회. 정상 종료와 기기 이상을 구분하려면 서버에 촬영 세션 개념 필요 |
| 시각 타임존 | `updated_at`이 타임존 없는 문자열이라 앱 시계와 직접 비교 불가 (컨테이너 UTC ↔ 단말 KST) |
| `video_status` 누락 대응 | 응답에 해당 필드가 없으면 Gson이 null을 넣어 사고이력 조회 전체가 실패하던 문제를 앱에서 `none` 기본값으로 방어. 서버가 항상 내려주면 불필요 |
| 전화번호 검증 | 백엔드 정규식도 010으로 시작하는 10자리를 허용 중 |
| 함수명 불일치 | Python `get_current_user_id()`가 실제로는 이메일 반환. 현재 사용처 없어 무해 |
| 응답 형식 차이 | Python flat JSON / Kotlin `{success, message, data}` 래퍼. 명세 v3.0에 문서화돼 있어 앱에서 DTO·Retrofit 클라이언트를 분리 대응. 서버 변경 불필요 |
